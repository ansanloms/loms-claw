# セッション間の依頼 API

対象のチャンネル/スレッドのセッションへ依頼を渡す。依頼は対象スコープのキューに積まれ、そのスコープのセッション (文脈を持つ会話) を再開して処理される。結果は対象のチャンネル/スレッドへ投稿される。Discord への中継の投稿は残らない。

内部 API のポートは固定ではない。`config.json` の `claude.apiPort` (既定 3000) で変わる。次の例では `3000` を使う。

## 使いどころ

- cron のターンは固定の文脈 (`cron:<ジョブ名>`) で動くため、投稿先のスレッドで進行中の会話を知らない。スレッドの会話の文脈で発言させたいときは、投稿せずにこの API で依頼を渡す。
- cron のターンでは「今依頼を渡す価値があるか」を判断し、価値が無ければ API を呼ばずに終える。
- 自分が今いるスコープには使わない。現在のターンの後ろに積まれ、同じセッションで処理されるだけで意味が無い。

## エンドポイント

```
POST http://127.0.0.1:3000/sessions/{channelId}/messages
POST http://127.0.0.1:3000/sessions/{channelId}/{threadId}/messages
```

- `{channelId}` と `{threadId}` は Discord の ID (数字 17〜20 桁)。それ以外は 400。
- チャンネルへの依頼は `{channelId}` だけ。スレッドの ID を `{channelId}` に入れてはいけない (404)。
- スレッドへの依頼は、親チャンネルの ID を `{channelId}`、スレッドの ID を `{threadId}` に入れる。親が一致しないと 404。

## リクエスト

```json
{ "prompt": "依頼の本文", "source": "cron:touring-check" }
```

- `prompt` (必須): 依頼の本文。空白以外を 1 文字以上含むこと (空白だけは 400)。対象のセッションがそのまま受け取るので、相手が単独で理解できるように書く。
- `source` (任意): 依頼元の識別子。1〜100 文字。日本語や空白も使えるが、改行・タブなどの制御文字を含むと 400。cron から呼ぶなら `cron:<ジョブ名>` にする。注記に依頼元として入る。

## curl の例

```bash
# スレッドのセッションへ依頼する
curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"prompt":"今日の宿までの残りの道のりを一言添えて声をかけて。","source":"cron:touring-check"}' \
  http://127.0.0.1:3000/sessions/1234567890123456789/1234567890123456790/messages

# チャンネルのセッションへ依頼する
curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"prompt":"朝のニュースを要約して。"}' \
  http://127.0.0.1:3000/sessions/1234567890123456789/messages
```

## 応答

| ステータス | 意味                                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------- |
| 202        | `{"ok":true}`。キューに積んだ。処理の完了は待たない。                                                         |
| 400        | JSON が不正、またはスキーマ不一致 (`prompt` が空、未知のキー等)。                                             |
| 404        | チャンネル/スレッドが存在しない、このサーバ外、送信できない種別、bot に送信権限が無い、スレッドがロック中、`threadId` の親が `channelId` と一致しない。 |
| 429        | 依頼のレート制限の超過。                                                                                      |
| 503        | この機能が無効、または bot が終了処理中。                                                                      |

## 注意

- 対象の `active` 設定や `config.json` の `activeChannelIds` は見ない (自己メンションと同じ)。`active` でないスコープにも依頼は届き、応答はそのスコープへ投稿される。
- 同じターン内で相手の応答を待たない (ポーリングしない)。202 は受付であり、処理の結果ではない。
- レート制限は bot 全体で直近 10 分に 6 回まで。自己メンションとは別枠。超過は受付時にその場で 429 になる。202 を返した依頼は対象のキューに積まれて実行される。実行に失敗した場合は、対象のスコープにエラーが通知される。短時間に大量に投げないこと。
- 受けたセッションが同じ API で別のセッションへ依頼を渡す連鎖は、このレート制限で抑える。連鎖させる必要が無いかを先に考えること。
- 受けたセッションのプロンプト先頭には `[セッション間の依頼]` の注記が付く。`source` があれば依頼元も添えられる。その依頼は本人の発話ではない。
- 依頼で動くツールの承認ボタンは、対象のチャンネル/スレッドに出る。
