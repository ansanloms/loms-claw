# ピン投稿テンプレート

travel チャンネルにピン止めする「スケジュール投稿」の本文の書式。いつ作る・いつ更新する・frontmatter に何を記録するかは `SKILL.md` の「Discord ピン投稿」節が定める。ここは本文の形と URL の規則だけを定める。

## 書式

`<...>` は値プレースホルダ。本文は Discord の Markdown で、見出し記法 (`#`) は使わず太字で代用する。

```text
**<旅行名>** <YYYY-MM-DD (曜)> 〜 <YYYY-MM-DD (曜)>

**Day 1 (<MM-DD 曜>)**
- <HH:MM> <地点、または A → B の移動。補足があれば同じ行に短く>
<URL>
- <HH:MM> <...>
<URL>

**Day 2 (<MM-DD 曜>)**
- ...

**もちもの**
- <品名>
- <品名>

更新: <YYYY-MM-DD HH:MM>
```

- 見出し行: `title` と `start_at`/`end_at` の日付から作る。曜日は日本語 1 文字。通が複数になるときは末尾に `(k/n)` を付ける (例: `**稚内・宗谷岬** 2026-09-19 (土) 〜 2026-09-24 (木) (2/3)`)。1 通なら付けない。
- Day ブロック: ノートの「行程」の Day 見出しごとに 1 ブロック。行程に無い Day は作らない。行は時刻順に並べる。
  - 時刻は `HH:MM`。未定なら `—` を置く。
  - 1 行 1 地点または 1 移動。移動は `A → B` の形で書く。「移動」「宿泊」に書かれた内容 (フェリーの発着・宿のチェックイン) も、該当する Day の行として時刻順に混ぜる。
  - 予約番号・集合時刻・最終出発時刻のような当日に見る値は、同じ行の括弧内に短く書く。理由・検討経緯・過去の教訓は書かない。
  - 行の直下の行に URL を 1 本置く。URL を付けない行 (フェリー乗船中・帰宅等) はそのまま。
- もちもの: 任意。載せる条件は `SKILL.md`。載せるときはノートの「装備」から品名だけを 1 行 1 品で書く。
- 更新行: 本文を組み立てた時刻 (`date '+%Y-%m-%d %H:%M'`)。

## URL の規則

Google Maps URLs (https://developers.google.com/maps/documentation/urls/get-started) の書式を使う。プレビューを出さないため、送信・編集時は `flags: 4` を付ける (`SKILL.md`)。

- 地点 (宿・港・観光地・道の駅等): `https://www.google.com/maps/search/?api=1&query=<緯度>%2C<経度>`
- 移動 (陸路): `https://www.google.com/maps/dir/?api=1&origin=<緯度>%2C<経度>&destination=<緯度>%2C<経度>&travelmode=<mode>`
  - `<mode>` はバイク `two-wheeler`、車 `driving`、徒歩・登山 `walking`、公共交通 `transit`。ノートの `tags` と「移動」の記述から選ぶ。
  - 経由地があれば `&waypoints=<緯度>%2C<経度>%7C<緯度>%2C<経度>` を足す (区切りは `|` をエンコードした `%7C`、最大 9 地点)。
  - フェリー・鉄道の区間には経路 URL を付けない。乗降する港・駅を地点として書く。
- 座標は小数 4 桁 (約 11 m)。理由: 住所文字列を URL エンコードすると 1 本 300〜600 文字になり、2000 文字の 1 通に数本しか入らない。座標なら 1 本 120 文字程度で済む。
- 座標の取得は国土地理院住所検索 API で行う (`jartic-traffic-volume` skill のジオコーディングと同じ API)。

  ```sh
  curl -sS -G 'https://msearch.gsi.go.jp/address-search/AddressSearch' --data-urlencode 'q=<住所または施設名>'
  ```

  - 応答の `geometry.coordinates` は `[経度, 緯度]` の順。URL には緯度・経度の順で入れる。
  - 候補が複数のときは `properties.title` を見て、ノートの都道府県・市町村に合うものを選ぶ。先頭を機械的に採らない。
  - ノートに住所があれば住所で引く (施設名より一意に決まる)。
  - 引けない、または「〜付近」のように地点が曖昧な場合は、その行だけ座標の代わりに地名・住所を URL エンコードして入れる。
  - 会話の中で引いた座標はノートの該当箇所 (「移動」「宿泊」等) に `(35.6812, 139.7671)` の形で控え、次回の更新で再利用する。
- ノート本文に住所ベースの経路 URL が既に書かれていても、ピン投稿にはそれを転記しない。上の規則で組み直す。

## 例

`20260919-wakkanai-soya.md` の Day 1〜2 を組んだ形 (座標はプレースホルダのまま)。

```text
**稚内・宗谷岬ツーリング** 2026-09-19 (土) 〜 2026-09-24 (木) (1/2)

**Day 1 (09-19 土)**
- 12:30 自宅 → 新潟港フェリーターミナル (最終出発 12:30、集合 21:30)
https://www.google.com/maps/dir/?api=1&origin=<緯度>%2C<経度>&destination=<緯度>%2C<経度>&travelmode=two-wheeler
- 22:30 新日本海フェリー らいらっく 新潟発

**Day 2 (09-20 日)**
- 16:45 苫小牧東港着
https://www.google.com/maps/search/?api=1&query=<緯度>%2C<経度>
- 18:30 苫小牧ホテル杉田 チェックイン (予約 4127)
https://www.google.com/maps/dir/?api=1&origin=<緯度>%2C<経度>&destination=<緯度>%2C<経度>&travelmode=two-wheeler

更新: 2026-09-08 23:40
```
