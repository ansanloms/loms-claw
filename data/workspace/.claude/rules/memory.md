# メモリ管理

ワークスペースの `memory/` 配下にファイルベースの永続メモリがある。ディスクに保存したものだけが記憶。隠れた状態は存在しない。

Claude Code 組み込みの auto memory（`~/.claude/projects/` 配下の memory/）は settings.json の `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` で無効化している。記憶の保存先はこのルールが定める `memory/` のみ。auto memory 側には書くな。

## ストレージ構成

### memory/MEMORY.md（索引 + 横断的な好み）

長期記憶の入口。各ファイルへの索引と、分野を問わず常に効く好み・方針・制約だけを持つ。ファイルが存在しなければ `# Memory` という見出しだけのファイルを作成しろ。

#### 保存すべきもの

- ユーザの好み・方針・繰り返し出る要望
- 重要な判断とその理由
- 過去の会話で確定した事実（運用ルール等）

#### 保存すべきでないもの

- タスク（→ memory/TODO.md）
- 分野特化の長期知識・台帳（→ memory/knowledge/）
- センシティブな個人情報（→ memory/private/）
- 単発の出来事（→ memory/activity.md の変化ログ）
- コードや git 履歴から導出できる情報

#### 形式

- 箇条書きで簡潔に。1 項目 1〜2 行。
- カテゴリで分類（例: `## 好み・方針`, `## 買い物`）。
- 古くなった情報は削除または更新しろ。肥大化させるな。
- 長くなる内容は knowledge/へ切り出して索引からリンクしろ。

### memory/private/（センシティブな個人情報）

住所・身体情報・保険等を用途別に 1 ファイルで持つ（address.md / medical.md / insurance.md 等）。**MUST: private/ の値を出力してよいのは #private チャンネル（ID 1546352020884299908）だけ。** システムプロンプトで #private と案内されていない場所では、会話の文脈で言及が必要でも値をそのまま出力せず、#private で答えると返す。センシティブな個人情報の追加・更新はこのディレクトリのファイルにのみ書き、他のファイルへ複製しない。読むときは用途に対応する 1 ファイルだけを読む。新しい用途が必要になったらファイルを増やし、MEMORY.md の索引に追記しろ。

ファイルが存在しなければ、上記の MUST をファイル冒頭に記載したうえで作成しろ。

### memory/knowledge/（分野別の長期知識）

所有ギア台帳・登山/ツーリングの教訓など、分野ごとの長期知識。ファイル名は分野名を先頭に置く（gear.md / hiking.md / hiking-gear-checklist.md 等）。教訓の追記先は分野の主ファイル（hiking.md 等）。新しい分野が必要になったらファイルを増やし、MEMORY.md の索引に追記しろ。

台帳（gear.md / bike.md 等）と教訓（hiking.md / touring.md 等）は書き分ける。

- 台帳は品目ごとに「品名・型番・仕様 / 購入元・価格・導入日 / 導入理由 / 用途・注意」を持つ。無くしたときの補填と、なぜ持っているかの判断に使う。
- 訂正の経緯（「以前〜と誤記」「記録漏れ判明」等）は書かない。誤りは黙って直す。
- 出来事から得た教訓は分野の主ファイルへ書く。台帳には導入理由の 1 行と主ファイルへの参照だけを残す。
- 同じ品目をファイル内の複数箇所に書かない。複数の節から使う品目は 1 か所に本体を書き、他は参照にする。
- 品目が増えたら節を分野内の区分（車体 / ウェア / 積載 / 工具 等）で分ける。1 段の箇条書きに何でも並べない。

### memory/activity.md（最近の動向）

直近 1 ヶ月のユーザの行動・関心のサマリ。構成は `## 最新動向` と `## ここ1ヶ月の動向`（日付付き変化ログ、30 日で失効）。

- `## 最新動向` は cron ジョブ `check-profiles` が毎日全面更新する。会話セッションからは書き換えない。
- `## ここ1ヶ月の動向` は cron と会話セッションが共有する変化ログ。会話で得た、翌日以降も参照する価値のある出来事・決定は `- YYYY-MM-DD: 内容` 形式でここへ追記しろ（日次メモは廃止した。これが代替）。
- 1 日 1 行、同じ日付の行が既にあれば統合する。

### memory/TODO.md（タスク）

行動の管理。記憶ではない。運用は todo ルールに従う。

### memory/travel/（旅行ノート）

旅行 1 件につき 1 ノート。`travel-note` skill の手順で扱う。

## 参照ルール

- 過去の文脈・ユーザの好み・以前の判断が必要と判断したとき、memory/MEMORY.md を読み、索引から必要なファイルへ降りろ。
- ユーザが最近何をしているか・何に関心があるかを知りたいときは memory/activity.md を読め。
- TODO の参照・更新が必要と判断したときは memory/TODO.md を読め。
- 毎回読む必要はない。文脈から必要性を判断しろ。

## 書き込みルール

- 今後のセッションで参照する価値があると判断したら保存しろ。振り分けは上記ストレージ構成に従う。
- 迷ったら:
  - 分野を問わず常に効く短い事実 → MEMORY.md
  - 分野の知識・台帳 → knowledge/
  - 単発の出来事 → activity.md の変化ログ
  - やるべき行動 → TODO.md
  - センシティブな個人情報 → private/
- 同じ内容を複数ファイルに書かない。昇格・移動したら元の記述を消せ。
- 定期的に MEMORY.md と knowledge/を見直し、古い・不正確な情報を整理しろ。
