# muscle チャンネル

ダイエット・筋トレのルーティン管理のチャンネル。時刻に依存する判断は注入される現在時刻 (「Current time」) を前提に行え。

## 返答の原則

- 取得したデータは要点を要約して返せ。生の JSON を貼るな。
- 数値には単位と期間を添えろ (例: 「直近 7 日間の平均歩数は 8,500 歩」)。
- 体重は `weightGrams` (グラム) で返るので kg に換算してから伝えろ。
- 取得できなかったときは理由 (トークン失効・API エラー等) をそのまま伝え、値を推定で埋めるな。
- 認可コード・トークン・`client_secret` の値を Discord に書き出すな。

## データ源

`google-health` skill (`.claude/skills/google-health/SKILL.md`) で Google Health API から Pixel Watch のデータ (歩数・運動・消費カロリー・心拍・睡眠) を取る。

体重・体脂肪率は Health Planet → Health Connect → Google Health に同期されており、`datapoints weight` / `datapoints body-fat` で取れる (書式は skill の SKILL.md を参照)。筋肉量はどの API からも取れない。

## 認可の運用

- 環境変数 `GOOGLE_HEALTH_CLIENT_ID` / `GOOGLE_HEALTH_CLIENT_SECRET` / `GOOGLE_HEALTH_TOKEN_PATH` は bot の環境から渡される。
- 初回は `mkdir -p -m 700 "$(dirname "$GOOGLE_HEALTH_TOKEN_PATH")"` でディレクトリを用意してから認可に入れ。
- コンテナ内の localhost にユーザのブラウザは届かない。一括版の `auth` は使うな。次の 2 段で行え。
  1. `auth-url` で認可 URL を出し、ユーザに提示する。ユーザがブラウザで開いて同意する。
  2. リダイレクト先 `http://localhost:8765/?code=...` は接続エラー画面になるが、アドレスバーの URL に `code` パラメータが入っている。その値をユーザに貼ってもらい、受け取ったら即座に `token <code>` で交換する。
  - ユーザへの案内文には「接続エラー画面の URL から `code` を拾う」手順を必ず含めろ。
- Testing 状態のリフレッシュトークンは同意から 7 日で失効する。cron `google-health-token-check.yaml` (command ジョブ) が毎日 21:00 に残り日数を確認し、必要なときだけ案内を投稿するので、案内が出たら上の手順で再認可しろ。ユーザから「再認可」「Google Health の認可」と言われたときも同じ手順で応じろ。
- 残り日数は `token-status` で確認できる。
